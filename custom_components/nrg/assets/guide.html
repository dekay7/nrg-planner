Understand your electricity costs. Find a better time to use energy. Coordinate the equipment you already have.

NRG Planner is an integration for Home Assistant, the home-automation platform. It combines your electricity rates with available household readings to suggest when using energy may cost less. If you choose, it can also manage electric-vehicle (EV) charging and a home battery through your existing Home Assistant integrations.

You can use it with any combination of an EV, home battery, and solar panels, including none of them. Start with advice and add equipment as needed.

Before you begin

  • Home Assistant 2026.10.2 or newer. This project targets 2026.10.2; newer releases may need compatibility checks. A standalone app is not provided.
  • An administrator account for installing and configuring the integration.
  • Your electricity plan, showing the variable supply and delivery prices and, if relevant, the credit for electricity you send to the grid.
  • Existing Home Assistant integrations for equipment you want to monitor or control. NRG uses their readings and controls rather than connecting to each manufacturer's account itself.
  • USD pricing. Rate inputs use cents per kilowatt-hour; other currencies are not currently supported.

Current availability: this is a private-review snapshot. Authorized reviewers can install it manually. HACS installation becomes available after the owner publishes and validates the repository; it is not currently in the default HACS catalog. See installation for the exact steps.

What can it do for my home?

Your home What NRG can provide
Grid electricity only Buying-price graphs and advice about moving a flexible task to a better time. A suitable power meter adds covered daily-cost estimates.
An EV Monitor charging and charge level; optionally plan charging toward the selected vehicle limit before departure. No home battery is required.
Solar panels Combine supported solar forecasts with demand and export credits to assess when using solar is worthwhile. No battery is required.
A home battery Monitor charge level and usable-energy estimates; optionally plan supported hold, home-supply, and grid-charge modes. Solar and an EV are optional.
A combination Compare their effects together, including charging losses, export credits, EV deadlines, and battery reserve.

The current model supports one planned EV and one stationary-battery system. Forecast.Solar is the supported optional solar-forecast adapter. ComEd hourly is one optional supply-price adapter; you do not need to be a ComEd customer.

NRG gives advice for a reference appliance, such as a task that uses 1 kWh over an hour. It does not automatically start dishwashers, laundry, heating, or other arbitrary appliances. It does not schedule forced battery sales to the grid.

The three ideas that make setup easier

1. Monitoring and control are separate choices

Enable the equipment your home has under Configure → Components. This shows its readings and relevant cards. Separately choose whether NRG may control the EV or battery. Choosing a measurement or control entity alone grants no permission.

New installations use Observation: NRG proposes a plan without issuing equipment commands. Control permits commands only for components whose individual control switches are enabled and whose checks pass.

For example, you can monitor a battery, let NRG manage the car, and leave the battery under its manufacturer's controller. See handover when you are ready to change who controls a device.

2. Buying and selling electricity have different prices

Your buying price = supply + delivery. Supply pays for electricity; delivery covers the variable cost of bringing it to your home. Each can be flat, time-of-use, or an external price feed, independently of the other.

Example only: 8¢ supply plus 4¢ delivery means 12¢/kWh to buy. A task using 2 kWh would cost 24¢ for that energy. If an all-in feed already includes delivery, enter 0 for separate delivery so it is not added twice.

Export credit is what your plan credits for electricity sent back to the grid. Set it separately; it may be lower than the buying price. Free-looking solar can still have a cost: using it now may mean giving up an export credit.

All numeric tariff fields begin unset. Blank means unknown, not free. Enter zero explicitly when it really applies. The initial export basis is No credit. See pricing for schedules and external feeds.

3. Measurements and predictions tell different stories

  • Measured: what a meter or device reports now, such as battery percentage or charging power.
  • Forecast or modeled: what may happen later, such as tomorrow's solar or a proposed charging start.
  • Observed cost estimate: metered power combined with configured prices during the time NRG actually covered.

A plan is not proof that a device is doing it. A low partial-day cost is not proof of a low bill. NRG reports missing coverage rather than treating it as zero. The planner compares a bounded set of feasible schedules; it does not promise a mathematically perfect plan or guaranteed savings.

What to have ready

Use a Home Assistant administrator account and Home Assistant 2026.10.2 or newer; this snapshot targets 2026.10.2. NRG runs inside HA, so end users do not need Python, Node.js, or build tools. Generated dashboards and the handbook are already included.

The HA configuration directory is the folder containing your configuration.yaml, commonly /config on Home Assistant OS. Open it using your existing file-management method, such as File editor, Studio Code Server, or a network share. Other installation types may keep it at a different path.

Private review

HACS requires a public GitHub repository. While this repository remains private, install as follows:

  1. Download and extract the repository using an authorized GitHub account. On GitHub, Code → Download ZIP provides a copy of the selected branch.
  2. Open your HA configuration directory. Create custom_components there if it does not exist.
  3. Copy the repository's custom_components/nrg/ folder, including all its contents, into that directory. The result should look like this:

text <HA configuration directory>/ configuration.yaml custom_components/ nrg/ __init__.py manifest.json assets/ dashboards/ ...

  1. Restart Home Assistant.
  2. Open Settings → Devices & services → Add integration, search for NRG Planner, and follow the quick start.

No SSH deployer or site file is needed. If NRG does not appear, see troubleshooting.

No Git history, tests, development tools, or repository data files belong in the installed component directory beyond the files already under custom_components/nrg/.

HACS after publication

Add https://github.com/dekay7/nrg-planner in HACS Custom repositories, category Integration. Download, restart HA, and add the integration through Devices & services. Default-catalog approval is not required for this custom-repository path.

All integration assets, dashboard definitions, and the generic handbook are inside custom_components/nrg/ and are delivered together. HACS does not edit your configuration, enable device control, or register dashboard packages.

Optional dashboards

The integration's native entities and setup forms work without dashboards. For the bundled homeowner and admin views:

  1. Install ApexCharts Card through HACS and verify its JavaScript module is registered in Settings → Dashboards → Resources. NRG does not redistribute a copy or download it automatically. The chart templates target ApexCharts Card 2.2.3; recheck charts after frontend updates.
  2. Merge the following into configuration.yaml. If a homeassistant section or packages key already exists, merge rather than creating duplicate keys:

yaml homeassistant: packages: nrg_planner: !include custom_components/nrg/dashboard-package.yaml

For an existing !include_dir_named packages setup, instead add a file in that directory containing:

yaml !include ../custom_components/nrg/dashboard-package.yaml

  1. Check HA configuration and restart. NRG Planner and NRG Planner settings appear in the sidebar. The settings dashboard requires an admin account.
  2. Configure power meters in HA's built-in Energy dashboard for the live Sankey. NRG does not overwrite Energy preferences or create substitute meter readings.

The package includes recorder exclusions for large NRG diagnostic entities; merge them with any existing recorder configuration as needed. It does not contain tariffs, entity mappings for your hardware, or an automatically imported site file.

Bundled dashboards reference the integration's initial nrg_* entity IDs. If you rename those IDs, use your own dashboard copy and update the references. Keep customizations outside the integration directory so component updates preserve them.

The local handbook is served at /nrg-planner/guide.html when HA's HTTP integration is available. Open that path on your own HA address, or use the handbook link in Why? or Operation. Its contents are generic and do not include saved configuration. It includes troubleshooting, FAQs, a glossary, and privacy details. There are no scripts, external fonts, or external assets. Use browser Find to search and Print to save a PDF; reading a loaded copy needs no internet connection.

Updates and removal

For manual updates, replace only the component directory with a reviewed newer copy and restart. HACS updates follow the same component boundary. Integration options, learning, and ledgers use HA storage, not files inside the component.

Before removing NRG, release its control and establish the desired device baseline as described in operations. Remove the integration through Devices & services, remove its dashboard-package include if present, then remove its component through HACS or your manual file-management method. Check configuration before restarting. Use supported HA interfaces for stored configuration/history; do not manually edit HA's storage files.

Quick start

Goal: get useful advice before deciding whether to automate any equipment. You will need your electricity plan and the existing Home Assistant entities for any equipment you select. A Home Assistant entity is a single reading or control, such as a power sensor or charging switch.

In these steps, Configure → … means Settings → Devices & services → NRG Planner → Configure, then the named section. Work through setup with an administrator account. You can return to these forms at any time.

1. Install and select equipment

Follow installation, then add NRG Planner in Settings → Devices & services. Choose only the EV, stationary battery, and solar equipment you have. All three can be off. Monitoring and equipment control are separate.

Fresh installations start in Observation. Merely mapping a control entity does not grant command permission.

2. Enter your own electricity plan

Supply and delivery are independent. Either supports flat rates, time-of-use periods, or external HA entities/forecasts. ComEd hourly is an optional supply adapter. Rates use cents/kWh; external feeds also accept USD/kWh.

Rate fields start blank. Unset is unknown, not zero. If delivery is already included in your supply feed, explicitly enter zero for the separate delivery component rather than double-counting it.

For timed pricing, use Configure → Pricing periods. The optional four-period template has blank rates. Missing times and missing rates remain unknown.

Configure export compensation separately: No credit, Flat credit, or Supply plus adder. Both numeric export fields start unset. They are never inferred from delivery. See pricing.

3. Map available HA measurements

In Configure → Mappings, choose ordinary entities from existing integrations:

  • Grid and/or whole-home power for measured flows and cost estimates.
  • Solar power and Forecast.Solar sources if solar is enabled.
  • Battery power and SOC if a stationary battery is enabled.
  • EV connection, SOC, selected target, and optional power/energy/current readings.

Disabled components contribute known zero. Missing enabled equipment stays unknown. Review meter signs and whether the home meter includes EV charging in Configure → Meter conventions.

4. Review generic equipment assumptions

The capacity, power, efficiency, current, charging window, and departure fields are generic starting assumptions, not discovered specifications. Replace them with appropriate values for your equipment before relying on a schedule.

Installation dates start unset. Leave them unset until known. Learning uses only this HA installation's covered measurements; no household profile is bundled.

5. Configure optional controls

Compatible switches, numbers, and selects work directly. Configure → Control adapters maps battery modes, export settings, and optional command scripts to your device's actual behavior. Default option names are examples, not proof of compatibility. See adapters.

Map available protection and external-controller-priority flags. A selected guard must report the expected clear state; missing selected guards pause commands.

6. Review the plan

Use the native entities or install the optional dashboards. Compare the inputs, forecast coverage, and proposed actions with actual readings. Use the operations guide when transferring device control.

What a working setup looks like

  • The combined buying price matches your supply plus delivery. Blank prices call for a coverage check, not an assumption that electricity is free.
  • The plan has a current explanation; a grid-only home can use price advice with no EV, battery, solar, or site power meter.
  • Installed equipment readings make sense next to your meters or device apps. Daily cost appears only when sufficient site readings and prices are covered.
  • In Observation, a proposed charging/battery action is advice rather than a device command. You can stay in this mode for ongoing monitoring.

You are ready for everyday use. Read the homeowner guide for the graphs, common questions for typical decisions, or troubleshooting if an expected reading is missing.

Electricity price now

The large ¢/kWh number includes the selected supply plus delivery prices. They may each be flat, follow independent timed periods, or come from external feeds. Supply and delivery are also shown separately so the total is explainable.

Hourly current values can change before settlement. Contracted time-of-use rates change at the configured boundaries. Solid forecast lines represent published outlooks; dashed lines are estimates. A gap means price information is missing, not that energy is free.

The recommendation

  • Good time to use energy: now is among the better modeled opportunities.
  • Use energy as usual: shifting the reference task is not worth the difference.
  • Wait until …: a sufficiently cheaper complete window is available.
  • Waiting for dependable coverage: the information cannot support a full comparison.

The green segment marks a recommended window for the administrator's reference appliance, initially 1 kWh over one hour. The benefit concerns that task, not the entire house. Use energy whenever it is needed; this advice does not start or stop household appliances. Tap/hover a graph point to inspect it and use zoom/reset without changing equipment.

Solar can have an export-credit opportunity cost, and stored energy has losses and future value. NRG considers applicable equipment rather than assuming all solar or battery electricity is free. Homes without that equipment need no such assumptions.

Current power flow: the Sankey diagram

The Home Energy tab shows Home Assistant's built-in power Sankey card, the same live power-flow diagram as the Now tab of the Energy dashboard. It is unaffected by the dashboard's date selection and shows instantaneous power: the width of each band follows current flow from sources (grid, solar panels and battery) to consumers in the home.

The card reads the power entities configured in Settings → Dashboards → Energy, not planner estimates. Devices are grouped into floors and areas only when those are configured there. A meter that is not configured in the Energy dashboard is simply absent from the diagram; NRG never substitutes an invented or estimated flow for missing equipment.

Only the equipment this home has

EV cards, battery gauges and solar information appear only when enabled under Components. Monitoring does not mean NRG is controlling a device. Observed charging status uses local/provider power and connection readings; a proposed plan is shown separately.

With NRG EV control enabled, planned start/readiness aim for the selected limit by departure. The vehicle target is never raised by NRG. A shortfall means the model cannot meet that target under current assumptions. The administrator can use charge-now or a one-off departure override.

Battery percentage is measured. Available kWh uses the configured age-adjusted capacity and reserve, rather than claiming a measured battery-health test.

While Observation is selected, schedules are proposals. Devices may currently be following another controller. Monitoring-only equipment continues to use its own controls; NRG does not promise it will follow the modeled schedule.

Net energy cost today

Purchases minus export credits are estimated from covered meter readings and the contemporaneous supply-plus-delivery rates. A negative total means modeled credits exceed purchases over the covered time; it does not establish a cash payout.

Coverage matters. First days, restarts and missing readings are partial, not free. Fixed fees, capacity charges and unconfigured taxes are excluded. A home with no site power meter gets price advice but no claimed metered daily cost.

Use Why? and the linked complete handbook for explanations. The homeowner dashboard has no equipment or configuration controls.

Observation and Control

Observation calculates plans without equipment commands. Control authorizes only components separately enabled for NRG control. Mapping entities does not implicitly enable commands. Notifications are opt-in and never operate appliances.

Switching back to Observation stops new commands but does not restore settings already saved in equipment. Choose a desired physical baseline when transferring ownership, disabling control, or removing NRG.

Transfer equipment control

  1. Check component selections, rates, measurements, meter conventions, and modeled assumptions in Observation. Missing rates are unknown, not free electricity.
  2. Match actual mode/state names and command/readback capabilities. Do not map a forced-export mode to the logical "serve home" action.
  3. Record device settings needed for recovery: charging state/current/target and applicable battery mode, reserve, export policy, and grid-charge permission.
  4. Disable competing controllers and scheduled command automations. Use the optional external-controller-priority/protection mappings where suitable; NRG cannot automatically discover every other controller.
  5. Enable the desired EV/battery control switches and select Control.
  6. Compare acknowledged commands with readback and measured device response.

The equipment retains its own electrical protections. A service acknowledgment does not establish instantaneous power delivery or completion of a charge cycle.

Everyday controls

  • Charge now bypasses prices and the normal charging window, but respects connection, selected vehicle target, current limits, and mapped guards. It clears on completion, disconnection, or restart.
  • One-off departure overrides the daily time. An incomplete connected session stays overdue rather than silently moving to the following day.
  • Refresh reloads configured pricing/forecast inputs.
  • Reset learning removes learned profiles and calibration, preserving settings and the measured-cost ledger.
  • Notifications require opt-in, selected notify services, stable advice, a minimum modeled benefit, and non-quiet hours.

Missing data

Selected guard inputs must remain available and clear. Unsupported operations are not scheduled. Missing current/forecast prices or solar coverage prevent discretionary battery moves. Locally learned price estimates remain tentative; there is no bundled historical household fallback.

A missing or stale plan revokes charging grants where supported. Explicit charge-now can operate without price data when EV checks pass. Battery failures are reported independently of EV execution.

Recovery

Use an HA backup and a previously reviewed component version when recovering from an update. Backups may contain private settings and measurements. Keep them out of issues and repositories.

Release NRG control before enabling another controller. Restoring component files does not restore physical equipment settings or rewind saved options, learning, ledgers, or recorder history. Reestablish the desired device baseline explicitly.

The standard integration diagnostics download is an intentionally limited support summary. See privacy before sharing logs, screenshots, or state exports.

Do I need solar, a battery, or an electric car?

No. All three are optional and start disabled. A grid-only home can use price information and flexible-use advice. Add a suitable grid or home power meter for covered cost estimates. Turn off equipment you do not own under Configure → Components.

Does NRG replace Home Assistant's Energy dashboard?

No. The Energy dashboard remains useful for historical energy totals. NRG adds forward-looking advice, optional EV/battery planning, and covered cost estimates. The live power-flow diagram uses the meters already configured for HA Energy. Its setup is separate from NRG's measurement mappings.

For HA Energy pricing, use sensor.nrg_import_price_usd for buying and sensor.nrg_export_price_usd for export credit. The buying sensor already includes delivery. See accounting.

Do I have to install the dashboards or edit YAML?

The integration's setup forms and native entities work without the optional dashboards. NRG's own settings do not require YAML editing. The bundled dashboards do require the small package include described in installation, plus the separately installed ApexCharts Card for charts. YAML is a text-based configuration format; copy the example carefully and merge existing sections.

Will installation start controlling my equipment?

Fresh installations use Observation, with EV control, battery control, and notifications off. Monitoring, individual control permission, and operating mode are separate settings. Read operation and handover before enabling commands.

How do I stop NRG controlling a device?

Select Observation to stop new equipment commands, or turn off the relevant component's control switch. Settings already stored in the car, charger, or battery remain there. Set the desired device baseline in its own controls before enabling another controller. Handover and recovery explains the sequence.

Can I use my existing car, charger, or battery integration?

NRG uses compatible Home Assistant measurements, switches, numbers, and selects rather than requiring a particular brand. Compatibility depends on the operations and feedback that your integration exposes. Tessie is not required; compatible Teslemetry entities can be used directly. TeslaMate can supply readings, but charging control needs a separate command integration or suitable HA scripts. See integrations and adapters.

Does it raise my car's charge limit?

No. The selected vehicle target is read-only to NRG. It plans toward that limit using the available time and configured charging assumptions. A shortfall means the model cannot reach the selected target by departure under those conditions. Use Charge now or adjust the departure override when appropriate; see everyday controls.

Why wait when the buying price is negative or solar is producing?

The relevant price includes supply plus delivery. Negative supply can still leave a positive total. Solar used at home may give up an export credit; battery energy has conversion losses and possible future value. Advice also compares a complete run of your reference appliance rather than one cheap moment. See the homeowner guide.

Why does NRG recommend using energy as usual on a flat rate?

If shifting the complete task offers too little modeled benefit, that is the expected recommendation. Solar, export credits, or a controllable battery may still create differences, but a flat grid rate alone does not make one hour cheaper than another.

Does the displayed cost equal my bill or show money saved?

No. Today's net energy cost estimates covered grid purchases minus export credits. Missing readings and restart downtime reduce coverage. Fixed fees, capacity/demand charges, and unconfigured taxes are excluded. Credit banks and billing restrictions are not reconstructed. Modeled plan costs and appliance benefits answer different questions; accounting explains them.

Can it manage multiple EVs, other currencies, or timed battery exports?

The current scope is one planned EV, one modeled stationary-battery system, and USD-denominated pricing. It does not schedule forced battery exports or arbitrary household appliances. Export permission is not a sale schedule. See how it works and alternatives for context.

Does it need the internet or an NRG account?

There is no NRG account, analytics, or telemetry-upload service. Planning, saved settings, and learning run in Home Assistant. Flat or configured timed prices need no online price feed. ComEd and solar forecasts depend on their providers, and your selected equipment integrations or notification services may use the cloud. The bundled handbook needs no external assets. See privacy.

How long does learning take, and can I turn it off?

NRG uses the fallback assumptions until enough well-covered observations exist. Solar calibration starts after six valid daylight hours; EV calibration needs qualifying charging sessions; household learning builds from covered hours over time. Each switch can be turned off independently. Reset learning clears profiles and calibration while keeping settings and the measured-cost ledger. See learning for the exact requirements.

What stays saved when Home Assistant restarts?

Settings, source mappings, learned summaries, and cost ledgers use Home Assistant storage. Charge now is session-only and clears on restart; it also clears on completion or disconnection. A one-off departure persists until cleared and takes precedence over the daily time. Restart gaps are not filled with invented use. The operations guide covers updates and recovery.

Is NRG free, and where do I ask for help?

NRG is MIT-licensed. Home Assistant hardware, electricity, and third-party integrations or services may have their own costs. The maintainer is @dekay7. Follow getting help to prepare a useful report. This snapshot's repository access is limited to authorized reviewers until publication.

The prominent buying price

Buying price at a time = supply price at that time + delivery price at that time

The schedules are independent. A flat supply contract can have variable delivery, and a flat delivery rate can accompany variable supply. You can also use two different time-of-use schedules or external feeds. ComEd is only one optional supply source; it is never used as a fallback for another provider's missing rates.

Prices are entered in cents/kWh, converted once to USD/kWh internally. Negative rates remain signed. A −2¢ supply price plus 6¢ delivery still costs 4¢ to import. These are illustrative numbers, not defaults. All numeric rate inputs start unset; unknown rates remain unknown until supplied. Enter zero explicitly if applicable.

Editing timed periods in HA

  1. Open Settings → Devices & services → NRG Planner → Configure → Pricing periods.
  2. Choose Supply or Delivery.
  3. Add a period, edit/remove an existing one, or start an empty schedule with the four-period example.
  4. Enter the name, start, end, rate and starting weekdays.
  5. Select Time-of-use supply and/or Time-of-use delivery on the Tariff page for the components whose schedules should operate.

The template starts with these times. Its rates are blank until you enter them:

Period Starts Ends Supply rate Delivery rate
Morning 6 a.m. 1 p.m. Your rate Your rate
Mid-Day Peak 1 p.m. 7 p.m. Your rate Your rate
Evening 7 p.m. 9 p.m. Your rate Your rate
Overnight 9 p.m. 6 a.m. Your rate Your rate

Each component has its own copy: changing delivery's peak time does not change supply's. The template never overwrites an existing schedule.

Boundary and weekday rules

  • Start is included; end is excluded. A 1 p.m. reading belongs to the period starting at 1 p.m., not the one ending then.
  • End earlier than start crosses midnight. Equal start/end means a 24-hour period.
  • Weekdays describe the day the period starts. Monday 9 p.m.–6 a.m. extends to Tuesday 6 a.m.
  • Two periods cannot overlap. The editor rejects that ambiguity.
  • Gaps and blank rates can be saved while you build a schedule. Their prices stay unknown, the coverage status identifies incomplete schedules, and those intervals do not authorize discretionary battery moves.
  • Times use Home Assistant's timezone. Repeated DST clock times use the same tariff; nonexistent spring clock times are skipped in real elapsed-time accounting.

For weekend rates that change exactly at midnight, split weekday overnight into 00:00–06:00 and 21:00–00:00, both Monday–Friday, then add 00:00–00:00 for Saturday/Sunday. This avoids a Friday overnight period overlapping Saturday's rate.

Direct controls and option names

Use Configure → Control adapters to match actual option/state names:

What the learning and calibration controls do

In this chapter
  • Solar forecast calibration
  • Calibrate EV charging estimates
  • Learn household demand
  • Solar alternative weight
  • Resetting or disabling learning

These controls improve estimates from observed data. They never alter recorded meter values, appliance behavior, battery settings or a vehicle's selected limit. They work only for installed components with enough valid measurements.

Solar forecast calibration

Purpose: correct a forecast that is consistently too optimistic or pessimistic for the actual installation.

Before an hour starts, NRG saves the combined age-adjusted forecast for that hour. Afterward, it compares it with the solar meter's covered production. It does not compare against a forecast updated after the result was already known.

After six valid daylight hours, it calculates:

Correction = total measured solar ÷ total previously forecast solar
Corrected future forecast = age-adjusted forecast × correction

For example, repeatedly measuring 8 kWh when 10 kWh was forecast suggests a 0.8× correction. If actual output is consistently higher, the factor can exceed 1.

The calculation uses up to 168 recent covered daylight hours within the retained history, excludes tiny/nighttime forecasts, and bounds the factor to 0.5–1.5. Mean absolute error in Details indicates how far the saved hourly forecasts missed. Cloud changes can still cause surprises: this corrects a persistent bias, not weather.

It does not infer individual-roof accuracy from one whole-system meter. Changing sources or age settings clears the old solar comparisons. Turning calibration off uses the source forecast and configured age correction without the learned multiplier.

Calibrate EV charging estimates

Purpose: estimate how much AC electricity and time the car needs to reach its already selected charge limit.

A valid session has at least five percentage points gained, five minutes, and good uninterrupted measurement coverage. The increasing AC energy counter and SOC change give:

AC kWh per percentage point = energy used by charging ÷ SOC percentage-point gain

Example: 9 kWh for a change from 60% to 70% suggests 0.9 kWh per point. Another 10-point gain is provisionally budgeted at about 9 kWh. This includes charging losses.

NRG keeps the last 12 valid sessions and chooses a conservative upper-percentile energy estimate. Covered charging power divided by measured/set current also gives power per amp; a conservative lower-percentile value helps avoid promising a finish time based on an unusually fast session. Details shows the effective estimates.

Missing meters, gaps and counter resets do not create learned sessions. Without a valid estimate—or with the switch off—NRG uses the fallback kWh/point and charging power you entered. No EV battery degradation percentage or health estimate is made.

Learn household demand

Purpose: predict ordinary household usage so storage and flexible-use advice can work around daily life.

NRG integrates the home power meter. If an EV is installed and separately measured, it subtracts car charging; otherwise it can learn while the car is known not to be charging. A home without an EV uses the whole-home reading directly.

An hour needs at least 80% valid coverage. Missing time is not learned as zero. Impossible/inconsistent meter combinations pause the relevant learning rather than creating a false zero-house baseline.

It keeps up to 28 days of hourly summaries, compares matching clock hours, and gives each older matching observation 0.9× the weight of the next newer one. After three matching observations, weekdays/weekends can have their own profile.

Example: if evenings repeatedly use more power than afternoons, the forecast reserves more energy for those evenings. An unfamiliar hour still uses your fallback. It predicts patterns rather than identifying individual appliances or controlling comfort settings. Turning learning off uses your explicit house-demand estimate.

Solar alternative weight

Purpose: combine multiple estimates for the same physical panels without counting their electricity twice.

For forecasts in the same physical coverage group:

Combined forecast = sum(forecast × weight) ÷ sum(weights)

For example:

Forecast for the same roof Energy Weight
A 10 kWh 1
B 14 kWh 3

The result is (10 × 1 + 14 × 3) ÷ 4 = 13 kWh. Equal weights give a simple average. With only one forecast, changing its weight changes nothing. A weight is not a panel count or capacity multiplier.

After averaging alternatives, forecasts for different physical arrays are added. A separate west roof forecast of 5 kWh would make the total 18 kWh. Weights are explicit user choices; the whole-system solar calibration is a separate operation.

Resetting or disabling learning

Each learning switch can be turned off independently. Reset learning clears the learned profiles, EV sessions and forecast comparisons, while retaining the measured cost ledger. Installation dates, manual assumptions, tariff periods and entity selections remain saved. Disabled/nonexistent components need no calibration setup.

The integration is installed, but no NRG dashboards appear

Dashboards are optional and are not registered automatically. Complete the dashboard package setup, check the HA configuration, and restart. The NRG Planner settings view appears only for administrators. You can configure and use native entities without these views.

Charts say Custom element does not exist or are blank

  • For apexcharts-card errors, install ApexCharts Card separately through HACS and verify its module in Settings → Dashboards → Resources. The bundled templates target version 2.2.3. Reload the browser after resource changes.
  • If the card loads but has no data, inspect NRG's buying price, pricing coverage, and source status. Chart lines omit missing or expired plan data.
  • An External supply/delivery current sensor alone cannot fill future hours. Add a supported forecast or use your contracted flat/timed rates.
  • If entity IDs were renamed, the bundled dashboard still refers to the initial nrg_* IDs. Update the references in your own dashboard copy.

Electricity price is unknown, too high, or 100 times wrong

Open Configure → Tariff and check supply and delivery separately.

  • Both components need a valid rate for the combined buying price. Blank means unknown. Enter zero explicitly if there is no separate delivery cost.
  • If supply already includes delivery, do not add delivery again.
  • Type rates in cents/kWh: a $0.12/kWh rate is 12, not 0.12, in a cents field. External sensors must declare supported USD/kWh or cents/kWh units.
  • For timed pricing, select the time-of-use plan as well as saving its periods. Check uncovered hours, blank rates, starting weekdays, and the HA timezone.
  • For external feeds, inspect the selected current/forecast entities, forecast attribute, timestamps, interval ends, units, and freshness.

Negative supply is not necessarily a negative total after delivery is added. See pricing for accepted interval fields and overnight rules.

Advice says Waiting for dependable coverage

NRG needs enough trustworthy information to compare a complete run of the reference task. Check price coverage first, then the forecasts and enabled equipment readings that apply to your home. A one-hour task cannot be compared using only one known 15-minute slot.

Turn off components you do not have under Components. A disabled component contributes a known zero; an enabled component with missing readings is unknown. Use Refresh after correcting inputs. Tentative price estimates are not the same as dependable published or contracted coverage.

Power flows are missing, reversed, or inconsistent

NRG's normalized readings mean positive grid = buying and positive battery = supplying the home. In Configure → Meter conventions, reverse the applicable reading only if your provider uses the opposite convention. Check whether the home meter includes EV charging so it is not added or subtracted twice.

Review Details → Local measurement quality and the power-balance residual. Mismatched meters can pause learning. Map power entities in W or kW rather than energy counters in kWh for live power roles.

The Sankey diagram has its own setup: configure actual power meters in Home Assistant's Energy dashboard. NRG's Mappings screen does not populate it. Missing meters are not replaced with forecast flows. See the homeowner guide.

The plan exists, but my car or battery is not following it

Read Operation → Control status before checking the device.

  1. Mode: Observation proposes only; select Control when you intend to hand over operation.
  2. Component permission: enable the relevant EV/battery control switch separately.
  3. Inputs: confirm connection, charge percentage, selected EV target, required controls, and their available feedback. A plan is not observed operation.
  4. Protection: selected guard entities must report the expected clear states. A missing selected guard blocks commands; it is not silently ignored.
  5. Command compatibility: match your actual option/state names under Control adapters. Read-only feedback needs a working command script if no direct switch, number, or select can perform the action.
  6. Ownership: check for a manufacturer's schedule or another automation overwriting settings. Follow control handover.

Writer authorized indicates mode and component permission, not that every device is ready. Protection guards, EV ready, and Battery ready identify additional checks. Commands and device response may take time; feedback should confirm settings. Do not map forced battery export to NRG's serve-home action.

My sleeping car's readings are considered old

Some integrations publish vehicle values only when they change. First confirm the home-charger connection and that the readings are still appropriate. You can provide a wake/refresh automation through the existing integration. Alternatively, EV → Allow saved vehicle readings while plugged in accepts available retained SOC/target/settings while the home connection is reported. It starts off and allows less-current estimates; it does not bypass connection, protection, or command-feedback checks. See reading freshness.

EV ready time is late or there is a departure shortfall

Check the daily departure, any one-off override, vehicle target, current charge, maximum/stable current, modeled charging power, energy per percentage point, and actual connection. Generic defaults are not detected hardware specifications.

Charge now bypasses prices and the normal charging window when EV checks pass. It does not raise the vehicle target or ignore current/protection limits. Clear an outdated one-off departure using Clear one-off departure. An incomplete continuously connected session stays overdue instead of quietly moving to tomorrow.

The battery will not grid-charge or export on schedule

Grid charging requires a supported charge action. If charge and hold share the same device mode, a separate grid-charge permission switch is needed; otherwise a distinct charge-capable mode can work. Missing trustworthy price/solar inputs, reserve, device readiness, or an enabled summer precaution can also limit moves.

NRG does not schedule forced battery exports. Battery export policy permits exports where a control exists; it does not request a timed sale. Without a mapped export control, configure that policy in the equipment's own app. See control adapters.

Solar totals look doubled or a source is unavailable

Add distinct physical arrays, but average alternatives covering the same panels. Do not add several sensors from one Forecast.Solar entry as separate independent forecasts. A whole-system forecast and a partial overlapping roof cannot be combined as separate coverage. Review each source's group and status.

For a consistently low prediction, check whether both provider calibration and NRG age correction are reducing the same output. Turn age correction off for a provider already adjusted to current panel output. A missing daylight forecast stays unknown; nighttime can be known zero. See solar sources.

Today's cost is absent, surprisingly low, or different from HA Energy

Check Today's cost coverage together with the net cost. Cost tracking needs sufficient grid/site power readings and contemporaneous prices. First days, missing readings, and downtime are partial. Price advice can still work without site metering.

NRG integrates covered power samples; HA Energy can use lifetime energy counters. Their totals need not match. Fixed fees and unconfigured taxes are outside NRG's variable-cost ledger. Changing a rate does not retroactively reprice recorded intervals. See accounting.

Learning or notifications do not seem to work

Learning: check the relevant switch and measurement coverage. Household hours need 80% valid coverage. Solar needs six valid daylight comparisons. EV sessions need at least five percentage points, five minutes, and covered AC energy readings from an increasing lifetime counter. Until then, configured fallbacks are expected. Learning explains each requirement. Reset only when you intend to discard learned profiles and comparisons.

Notifications: enable notifications and select existing notify services in Configure → Notifications. The feature sends stable wait-until advice only when its modeled benefit reaches your threshold and quiet hours permit it. A two-minute stability requirement prevents immediate messages; the default threshold is 25¢ for the reference task. No message is expected just because a price changed.

The handbook looks old after an update

Open it using a dashboard's handbook link; the generated link includes a content version to avoid an old cached copy. Reload the browser if needed. With a manual update, confirm the complete custom_components/nrg/ directory was replaced, including assets/guide.html and the bundled dashboards.

How NRG Planner makes decisions

In this chapter
  • Scope and objective
  • Time and prices
  • Measurements and statistics
  • EV candidates
  • Battery search
  • Household advice and execution

Scope and objective

NRG compares feasible plans to reduce purchases minus export credits, including storage losses, optional cycling cost and remaining stored-energy value. Ordinary household demand is forecast; applicable EV deadlines and backup reserve take priority. The calculation is pure Python. A separate guarded writer uses public HA services.

Every hardware component is optional. Only an enabled, controllable battery is scheduled. An uncontrolled EV's already observed charging can be extrapolated to its known target as a background load; it does not produce EV command permission. A grid-only home needs neither battery nor EV data for price advice.

Time and prices

The horizon covers 48 real hours, split into 15-minute intervals and exact tariff, departure, buffer and charging-window boundaries. Intervals carry UTC instants; contract times and weekdays use HA's timezone. Repeated DST clock hours receive the same time-of-use rate, while energy uses their real elapsed duration.

Supply and delivery are evaluated independently at every boundary, then added once. Both support flat, timed and external prices; supply additionally supports ComEd. External current observations are not extrapolated as future rates. Missing foreign utility data never receives a ComEd historical fallback. See pricing. Flat rates also start unset. The optional ComEd estimate uses only observations learned by the current installation; no historical profile is embedded.

For daily departure on a DST change, the first occurrence of an ambiguous local time is used. A nonexistent spring time shifts forward by the DST jump.

Measurements and statistics

Known absent equipment contributes zero; missing enabled equipment is unknown. Complete applicable site meters can derive a missing home/grid reading from solar + grid + battery = home, with the calculated basis identified.

At least once per minute, the previous valid sample is integrated only across gaps of at most 180 seconds. An hour needs at least 80% coverage to be learned; its covered energy is scaled to an hour. Missing/restart gaps are never zero observations.

House demand excludes separately measured EV charging. If that meter is unavailable, learning can continue while the car is known not to be charging. If EV power exceeds home power by more than 0.2 kW, or available site flows disagree by more than the larger of 0.3 kW / 5% of home power, relevant learning pauses. Details exposes quality and the balance residual rather than learning an impossible zero house load.

The recency-weighted hour-of-day profile uses up to 28 days; each older observation has 0.9× the next newer weight. Weekday/weekend matching is used after three matching observations. Missing profiles use the configured fallback.

Solar uses correctly grouped forecasts, optional compounded panel age and a bounded actual/forecast ratio after six covered daylight hours. Forecasts are frozen before the evaluated hour; later forecast improvements are not used as hindsight.

EV calibration uses covered sessions with at least five SOC points and five minutes. The upper 80th-percentile AC kWh/point sample from the last twelve valid sessions is conservative about required energy. Lower-percentile observed power/amp estimates help avoid overpromising charging speed. It does not estimate EV degradation. The learning guide explains all four controls with examples.

EV candidates

AC energy needed = (selected limit − SOC) × estimated AC kWh per percentage point

When EV control is enabled, compare cheapest-grid, solar-aware, earliest and latest feasible schedules. Solar-aware charging values direct surplus at foregone export credit and can lower current within its configured stable range. It increases available current if otherwise a feasible deadline would be missed.

Use the completion buffer first, then the actual departure and additional available time if necessary. Charge-now ignores price/window preferences. An incomplete continuously connected session remains overdue rather than silently moving to tomorrow.

A previous feasible EV schedule competes to reduce churn. Preserve it when the modeled improvement is below the selected threshold. Known-price charging periods are preferred over unpriced gaps before comparing cost. An estimate used internally for deadline calculations is not displayed as a known tariff or a free hour.

Battery search

For each EV candidate, search supported hold, serve the home, grid charge modes. No battery, monitoring-only battery, missing controls or invalid SOC yields no discretionary battery trajectory. No charge-capable mode/switch means grid charging is excluded rather than invented. Unknown current prices/solar permit hold only.

Grid charging is not scheduled alongside EV charging. The preserve-battery option also excludes serving the car from storage. The optional seasonal peak precaution is separate from tariff prices and starts off for non-ComEd configurations.

For round-trip efficiency r:

next stored energy = stored energy
                   + AC charging energy × sqrt(r)
                   − AC delivered energy / sqrt(r)

Capacity, room, reserve and modeled power constrain every transition. Age-adjusted capacity is baseline capacity × (1 − annual degradation/100)^age, with fractional years from elapsed days / 365.2425. An unset date does not invent age.

Search width is bounded to roughly 80 capacity bins, at least 0.5 kWh apart. Exact energy is carried inside bins and never rounded up. The least modeled-cost path per bin survives. This approximate search is not a global-optimum claim. Numerical ties favor less battery throughput, avoiding artificial flat-rate cycling.

Remaining energy receives a common replacement value from the cheapest known grid and solar refill opportunities, with losses and finite charging power. Refill is weighted up to usable capacity: a tiny solar surplus does not make the whole battery free to refill. Insufficient known refill energy uses the mean known buying rate for the remainder. Calendar degradation does not imply a cycling cost; optional wear cost defaults to zero.

Stored-battery sales are not scheduled or credited merely because export permission is allowed. The modeled serve mode supplies home demand; it must not be mapped to a forced export operation. Solar surplus exports when permitted/nonnegative, otherwise it is modeled as curtailed. Native response is checked separately.

Household advice and execution

Replay the selected modes with the reference appliance starting now or at each 15-minute boundary in the next day. Include its complete duration, foregone exports and end-of-horizon energy value. Only the contiguous trusted-price horizon competes. Tentative/gap prices remain distinguishable. Advice never operates an appliance.

Plans expire after seven minutes and replan every five minutes/on important changes. The serialized writer runs every thirty seconds and selects the applicable dated plan interval, so tariff/charging boundaries do not wait for a fresh five-minute plan. It rechecks ownership, revision, protection inputs, supported operations, limits and readback at command boundaries. A failed battery command does not by itself suppress independent EV checks.

Commands may take time to reach equipment. A battery may briefly supply a car before the hold takes effect. Requests and readbacks do not guarantee instantaneous power; the equipment retains its own electrical protections.

Settings are HA integration options. Compact hourly learning, dated caches and 62 daily ledgers use HA Store, saved periodically and on shutdown. Bootstrap YAML never overwrites existing UI options. The optional dashboard package excludes large plan/source/observation entities from recorder. The power-flow Sankey card is Home Assistant's built-in live data view of the Energy dashboard configuration; ApexCharts is a separately installed optional chart dependency used for timelines.

Prices, costs and savings estimates

In this chapter
  • Supply and delivery
  • Observed ledger
  • Different money figures
  • Built-in HA Energy

Supply and delivery

Internal prices use USD/kWh. Rate inputs and buying-price graphs use cents/kWh, converted once. At each instant NRG independently evaluates supply and delivery, then adds them. Different schedules, overnight periods, weekdays, flat rates and external intervals are supported. ComEd is an optional supply adapter only.

Published/outlook rates are not necessarily settlement values. Missing prices do not appear as zero. A known flat or configured timed rate does not need ComEd or an internet price feed.

Export credit is independent: selected supply plus an adder, flat credit or no credit. Export policy controls what is permitted where a supported device control exists; it does not itself establish compensation or a timed sale. Credit-bank, cash-out and billing-period restrictions are not automatically reconstructed.

Fixed customer fees do not change which hour is cheaper. Capacity charges and unconfigured taxes are excluded. The optional seasonal precaution is not an invented per-kWh cost or a claimed capacity-dollar saving.

Observed ledger

purchase cost = positive grid kW × hours × buying price at that time
export credit = negative grid kW magnitude × hours × configured export credit
net cost      = purchase cost − export credit

The previous observed power is integrated only over gaps of at most three minutes. Configured time-of-use boundaries split observed intervals exactly, including a boundary partway through a sampling minute. Current variable-feed rates remain contemporaneous running estimates. User rate changes do not retroactively reprice earlier observed intervals.

Missing price/grid data contributes neither cost nor cost coverage. Negative purchase costs and negative export credits remain signed, including adverse native exports that occur despite a request to stop them.

A complete set of applicable power meters can calculate a missing grid reading; the basis is identified in diagnostics. A home with no sufficient site metering does not get a claimed zero daily bill. Price advice still works.

Restart downtime is omitted rather than filled using a new price or counter jump. Coverage is cost-covered hours divided by real elapsed local-day hours, including DST. First days and outage days are partial. The ledger retains 62 days; learning reset preserves it. Daily energy figures cover observed intervals and can differ from the built-in Energy dashboard's lifetime-counter-based totals.

Different money figures

  1. Observed net variable cost: grid meter readings and contemporaneous rates, with explicit coverage. Not a complete settled utility bill.
  2. Modeled horizon cost: a schedule comparison, including storage terminal value and optional cycling cost. A ~ indicates estimated/uncovered future prices are involved. With no usable rates, the table says rates are needed.
  3. Reference-appliance benefit: modeled difference between complete start windows for the selected energy/duration, with applicable export/storage costs.

No annual saving is claimed from software scenarios. Validate predicted versus observed operation and reconcile actual bills.

Built-in HA Energy

Use sensor.nrg_import_price_usd as the buying-price entity if configuring HA Energy costs. It includes the selected supply and delivery methods; do not add delivery again. Its availability follows price coverage.

Use sensor.nrg_export_price_usd for export compensation. Changing Energy's price sources is a separate supported UI action; NRG does not rewrite historical records.

Free alternatives and intended community value

Home-energy planning already has capable free alternatives. NRG should be judged by useful operation and setup experience, not an unsupported claim of uniqueness.

Project Relevant overlap
Predbat Battery/solar forecasting, import/export pricing, and EV coordination across many inverters. Its current license permits free personal use; installation is a separate HA app/container.

A native HA integration with UI-configured, independent supply and delivery tariffs, separate export compensation, and coordinated optional EV/battery/solar planning through existing HA entities. Software scenario tests do not establish actual household savings, broad device compatibility, or ease of installation. A useful beta should validate setup effort, plan comprehension, restart/update behavior, and measured execution across independently configured homes and tariff types. Financial claims need measured operation and appropriate bill reconciliation.

The original private household data is neither required nor distributed for this validation. Test scenarios in this repository are invented.
